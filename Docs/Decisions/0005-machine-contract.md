# ADR 0005: explicit diagnostic codes and compiler-owned discovery

Accepted 2026-11-09. Agents need to distinguish source/input/compatibility/incomplete-execution failures without parsing human prose. This increment hardens the host contract, not the language syntax or runtime semantics.

## Decisions

- Add an explicit payload-free diagnostic-code enum with pinned wire spellings. Every constructor chooses a code; legacy `kind` derives exhaustively from it. No inference from message substrings and no public internal Rust enum/index serialization. Preserve message, half-open UTF-8 source span and optional JSON Pointer path; absent path stays omitted. Messages remain non-normative human text.
- Codes cover request/schema/operation/transport, syntax/name/type/purity, overflow vs zero divisor, reversed domains, replay specification/receipt, artifact compatibility/integrity/reproduction, input target/arity/type/canonical integer/field errors, and individual limit reasons. Unknown-name codes retain legacy Type kind rather than introducing a Name kind.
- Preserve report outcome semantics independently from codes: oversized dispatch is Request/Error; blocked probes retain legacy Limit/Unknown even after top-level faults; artifact reproduction can be overall Unknown with Artifact diagnostic. Never derive every report status solely from diagnostic kind/code.
- Code meanings and code-to-kind mappings are stable and never reused. New codes are additive; consumers tolerate unknown codes and fall back to kind/status. Discovery and diagnostic contract versions are separate from exact compiler semantics identity. This additive contract preserves semantics-5, existing hash material, ghost/artifact acceptance and execution keys.
- Add source-independent non-executing `capabilities` operation and native `wisp capabilities`. The dispatcher retains its existing required `source` field for all operations; the documented discovery request is `{"op":"capabilities","source":""}`. Avoid changing missing/null/duplicate/unknown-field behavior or normalizing raw arguments/artifacts. Known-but-unused fields keep their existing policy; discovery never reflects their contents.
- One bounded compiler-generated discovery document exposes schema versions, exact compiler, supported operations/actual features, core permissions, exact defaults/ceilings/units/exclusions, artifact compatibility/authentication limits, diagnostic codes, uncertainty and relative `Docs/` contracts with small runnable examples. No wishlist features, executable instructions, proof/security certification or performance superiority claims. Cap discovery serialization at 32 KiB and test it. Request cap remains 1 MiB; source and raw call args are 64 KiB. Logical counters are not allocator/process bounds, output caps exclude metadata.
- Publish the same compiler-generated document at `/wisp/agent.json` during the static build; verify native/WASM/static-manifest agreement and runnable examples. Agent documentation links the manifest and diagnostic reference; Human docs explain meaning/limits. No backend, credentials, telemetry, automatic repair or language IO added.

## Challenge and acceptance

Astra independently challenged agent needs and highlighted legacy kind/status exceptions, CLI-created diagnostics, raw JSON compatibility, missing-source behavior, fail-fast checking and unknown-code fallback. Require exhaustive code tables, arithmetic/limit distinctions, nested probe/replay/artifact/CLI diagnostics, malformed/duplicate/null requests, cap boundaries, compile-before-input ordering, no partial results, exact native/WASM manifest equality and existing pinned artifact/key compatibility. Native host IO/usage failures remain stderr/exit 2 without guaranteed diagnostic JSON; legacy --json semantic exit 0 remains.
