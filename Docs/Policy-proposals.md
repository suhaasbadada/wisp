# Read-only pinned policy proposals

`examples/policies/propose.py` checks caller pins, fetches compiler context,
prepares one guarded body and reviews the exact candidate against unchanged saved
cases. It never applies proposals or writes policy/expectation files. Rust is the
only language implementation; Python does not parse Wisp or choose expectations.

## Authored reservation example

```sh
cargo build --locked
python3 -B examples/policies/propose.py \
  --project examples/policies/project-before.json \
  --policy reservations --function decide \
  --expected-guard-file examples/policies/maintenance.guard.json \
  --replacement-file examples/policies/maintenance.body.txt
```

One ASCII-safe JSON record returns exit 0: context Ready, preparation Ready,
review Pass with seven passing expectations, two changed cases and fourteen fresh
before/after attempts. This repairs the already-authored rounding/expiry example;
it is not a new blind task, user adoption, model-reasoning measurement or language
comparison. Existing sources, cases and adverse workflow outcomes remain unchanged.

The committed guard is frozen, not regenerated by this command or CI. Drift needs
deliberate review, not automatic adoption/expectation repair. The replacement is
the Rust-indexed after-body bytes plus a final newline; the whole candidate is not
claimed to byte-match the after source file.

## Inputs and gates

Required flag/value pairs: `--project`, `--policy`, `--function`,
`--expected-guard-file`, `--replacement-file`. Optional: `--budget` (0–65536 text
bytes, default 4096), `--wisp` (trusted binary, default checkout
`target/debug/wisp`). Unknown/duplicate flags, overrides, refresh/retry and Apply
are rejected. Input files are UTF-8; `-` is not stdin shorthand in this driver.

Guard JSON is at most 16,384 bytes, with strict scalar Unicode/depth/duplicate
handling and exactly `{policy_id,manifest_hash,source_revision,suite_file_hash,compiler}`.
Copy the intended policy's MCP discovery `bridge.call_guards` entry only after
reviewing that snapshot. Native discovery exposes the same values. Hashes identify
bytes, not authorship, understanding, intent or permission. There is no hidden
capture-and-adopt mode.

Discovery is nonexecuting. Authored pins are compared before focus or replacement
IO. Guarded focus supplies the body hash from Rust graph metadata; replacement is
bounded to 65,536 UTF-8 bytes. The exact prepared source/revision enters saved-suite
review. Every native operation independently enforces pins; intervening drift
fails closed, without modifying guard files or weakening cases.

## Results and limits

The version-1 record has `mode:proposal`, `status`, `phase`, `policy_id`, `function`,
`expected_guard`, `approval:not_granted`, `applied:false` and full native `context`,
`preparation`, `review` wrappers. Unreached stages are null. Phases:

- `context_rejected`: received Error/Unknown; no preparation or review.
- `preparation_rejected`: received Error/Unknown; no case review.
- `reviewed`: received Pass/Fail/Error/Unknown, not necessarily acceptance.

Exit 0 Pass; 1 Fail/Error; 3 Unknown; 2 host/configuration/input/transport/closed
stdout. Host failure emits generic stderr, not successful JSON. Lost responses or
closed consumers can follow case attempts: exit 2 is not evidence of zero execution.
There are no retries. Context/preparation do not execute; review can make fresh
attempts even with Error/Unknown outcomes.

Reports contain full candidate/graph/case data. Text budgets are not total output,
memory or time bounds; use an outer job deadline and treat captures as policy
data. Documented commands use `-B` to suppress Python bytecode caches. The driver
code writes only stdout/stderr; callers own safe capture to a new
destination. Trusted-binary/stable-filesystem assumptions remain: not a hostile
executable or concurrent-filesystem sandbox. Finite Pass is not whole-project or
composed acceptance, requirements completeness, approval or deployment authority.

CI retains `project-proposal.json` with existing project evidence, separately from
SDK reports. See [Projects](Projects.md), [Python client](Python-client.md) and
[workflow gates](Workflow-gates.md).
